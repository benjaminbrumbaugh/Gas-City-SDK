# sdk-xlc diagnostic plan

counter: 3
bead: sdk-xlc
scope: Investigate the reported Dolt integration baseline failures and
produce durable evidence for the witness/refinery without changing unrelated
product behavior.

## Full plan, tasks, and subtasks

1. Establish provenance and workspace boundaries.
   - Confirm the assigned bead, target branch, worktree, and current origin/main.
   - Record `metadata.work_dir`, `metadata.branch`, and `fork_sha`.
2. Reproduce the reported failure cluster on the documented test layer.
   - Run the bounded-process fallback test.
   - Run each compact-script race/drift test named by the bead.
   - Capture exit status and focused output without masking failures through pipes.
3. Trace the failures to their owning layer.
   - Inspect the test harness and compact implementation only as needed.
   - Compare failure symptoms against Dolt/beads server health and logs.
   - Check history for an existing fix or known environmental prerequisite.
4. Decide whether this bead needs a source change.
   - If a narrow, reproducible product defect is found in scope, add a TDD test
     first and implement the minimal fix.
   - If the failures are pre-existing infrastructure/test-environment failures,
     preserve evidence and make no source change.
5. Verify and hand off.
   - Run the relevant affected tests and required quality checks for any source
     delta; otherwise run focused reproductions and baseline checks.
   - Append a concise diagnosis to the bead, commit only reviewable artifacts,
     push the per-bead branch, and reassign the open bead to refinery.

## Architectural changes

Expected default: none. This is a diagnostic bead. Any source modification
must remain within the beads/provider or test-harness boundary and must not
leak DoltLite assumptions into generic SDK paths. Do not alter domain behavior
solely to make a baseline test pass.

## Test and evidence plan

Target truth: whether the named failures are caused by current Gas City code,
the examples/bd/dolt harness, or the live Dolt data plane.

Required evidence layer: the named Go tests and their direct harness output,
plus bounded Dolt health/process/log diagnostics when the tests exercise the
server. These observe test/harness behavior and data-plane reachability; they
do not prove unrelated packages or end-to-end orchestration correctness.

Useful but insufficient proxies: a single `go test` pass, a clean `git diff`,
or `gc dolt status` alone. Tempting false completion: changing expectations,
skipping the failing tests, or restarting Dolt until the tests pass.

If this plan succeeds and the original bug remains, the likely cause is an
unobserved race or a mismatch between local and CI Dolt configuration. Keep
the exact commands, statuses, and relevant logs so a later owner can rerun
the same layer.

## Stability and blocker strategy

Prefer read-only probes. Never restart Dolt without the prescribed four-step
diagnostic capture and explicit authority. Preserve unrelated working-tree
content. If a source fix is required, keep it minimal, add regression coverage,
and run the affected tests before handoff. If no source fix is justified, the
bead notes are the durable output and the branch may carry only this plan/log
artifact if the workflow requires a commit.

- Inspect test ownership/history in parallel with health diagnostics.
- Keep any source change and its tests serial after the ownership decision.

## Planning pass 1 — initial review

The plan covers workspace provenance, direct reproduction, ownership tracing,
the source-change decision, and handoff. It explicitly separates target truth
from proxies and preserves the no-restart safety boundary. No-change decision:
do not add a fix or alter expectations until the named failures are reproduced
and assigned to a code layer.

## Planning pass 2 — critique and critical evaluation

Critique: the initial plan could accidentally overclaim from a focused test
run, and the phrase "relevant Dolt guidance" could leave evidence collection
underspecified. It also needs an explicit check that the test process and Dolt
server observe the same database/configuration.

Critical evaluation of that critique: these are real risks, but widening to a
full suite would add noise and increase shared-data contention. Tighten the
plan instead: capture exact package/test selectors, environment/database
identity, and server health around failures; keep broader checks proportional.

Roll-up into critique: retain focused tests as the primary evidence layer, add
configuration/database identity to the diagnostic record, and label every
result as pass/fail/reproduced/not reproduced rather than infer causality.

Roll-up into plan: section 2 must record selectors and environment; section 3
must correlate test harness database identity with Dolt process/health/logs;
section 5 must report what the evidence proves and does not prove.

No-change decision: still no source edits, restarts, expectation changes, or
full-suite claims before correlation.

## Planning pass 3 — final critique and roll-up

Critique: the revised plan still permits a plan/log-only commit that may be
undesirable if the repository treats diagnostic notes as bead-only output, and
it does not require checking historical evidence before inventing a fix.

Critical evaluation: the project instructions explicitly require feature
archaeology before rebuilding missing behavior, so history must precede any
implementation. The artifact policy also requires cleanup of temporary logs;
the durable bead note should carry the conclusion even if temporary captures
are removed.

Roll-up into critique: add a history search before implementation and define
that temporary captures are deleted or retained only when explicitly useful;
keep the plan as the required review artifact and avoid committing raw logs.

Roll-up into plan/tasks/subtasks: section 3 now includes history/branch
archaeology; section 5 requires a clean artifact boundary, a concise bead note,
and no raw diagnostic dump in git. Any source change remains conditional on a
reproduced in-scope defect.

Lost-information check after three passes: no initial requirement was dropped;
the final plan retains provenance, direct reproduction, layer ownership,
proxy-audit answers, stability constraints, history search, test gates, and
handoff requirements. The only deliberate narrowing is excluding broad noisy
tests and raw logs unless evidence requires them.

Final no-change decisions: do not modify production behavior, do not rewrite
tests to match a baseline failure, do not restart Dolt without explicit consent,
and do not claim the full suite is healthy from focused evidence.
